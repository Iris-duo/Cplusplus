## 1. 内存和地址

### 1.1 内存

在讲内存和地址之前，我们先看一个生活里的例子。

大学生住宿舍，如果一栋宿舍楼没有楼层编号、也没有寝室编号，把 A 同学随便安排进一间寝室，再让 B 同学去找他，会非常费时费力。但只要给每一间寝室编上门牌号，B 同学就能很快定位到人。

计算机管理内存的逻辑与此完全一致。CPU 处理数据时，数据要从内存读进来，运算完成后结果也要写回内存。

![CPU与内存之间的数据往来](https://aka.doubaocdn.com/s/E0bs7hhlx7)

*图 1-1　CPU 与内存之间的数据交换*

那我们电脑上的 8GB、16GB、32GB 内存，究竟是怎么被高效管理的？

内存会被划分成一个个**内存单元**，**每个内存单元的大小固定为 1 字节**。

- 内存单元 → 宿舍房间
- 1 字节 = 8 个 bit（比特位）→ 八人间宿舍里的 8 个床位
- 每个内存单元都有唯一编号 → 宿舍的门牌号，这个编号就叫**内存地址**

有了地址，CPU 就能一步定位到目标内存单元，完成读写。

> **概念区分**：内存地址 = 地址 = 指针。指针本质上就是内存地址。

### 1.2 硬件层面是如何编址的

计算机内部各硬件模块相互独立，硬件之间传递数据必须靠物理线路连接。CPU 和内存之间有海量数据交互，二者同样通过**总线**相连。

![CPU与内存之间的三类总线](https://aka.doubaocdn.com/s/u5FrDUeR2L)

*图 1-2　地址总线、数据总线、控制总线*

CPU 想读写内存中某个字节的数据，就必须知道这个字节在哪儿，因此要对内存进行编址。编址不是在软件里"记"出来的，而是硬件设计时就定好的约定——就像钢琴琴键上没有印简谱，但演奏者知道每个键对应哪个音。

- 32 位机器有 32 根地址总线，每根总线只有 0/1 两种电平状态；
- 32 根地址线能组合出 $2^{32}$ 种不同状态，每一种状态对应一个内存地址；
- CPU 把地址信号通过**地址总线**发给内存，内存按地址找到对应存储单元，再把数据通过**数据总线**回传给 CPU，整个过程由**控制总线**协调。

所以理论上 32 位机器的寻址能力是 $2^{32}$ 字节，也就是 4GB。

## 2. 指针变量和地址

### 2.1 取地址操作符 `&`

C 语言中定义变量的本质：**向内存申请一块连续的内存空间，用来存放数据**。

```c
int a = 0;
```

变量 `a` 占 4 字节，这 4 个字节中的**每一个字节**都有自己的独立地址。

![int a = 0 占用的4个字节](https://aka.doubaocdn.com/s/eeGVX7fgHp)

*图 2-1　一个 int 变量占用 4 个连续的内存单元*

对变量取地址 `&a`，拿到的是**这 4 个字节中地址最小的那个字节的地址**，也就是该变量的起始地址。

![对 a 取地址后内存窗口显示的值](https://aka.doubaocdn.com/s/tl2ALUAgeJ)

*图 2-2　调试时在内存窗口观察 a 所在的 4 个字节*

以 `int a = 0x11223344;` 为例，把 `&a` 打印出来，再去内存窗口对照：

![&a 打印结果与内存窗口地址一致](https://aka.doubaocdn.com/s/N7UaywIUJz)

*图 2-3　`printf("%p", &a)` 的结果与内存窗口地址完全对应*

可以看到两个细节：

1. **`&a` 显示的正是编号更小的那个字节的地址**（本例 `0x005DFC74`），它下面一个单元是 `0x005DFC78`，相差 4 字节——正好是一个 int 的大小；
2. 内存窗口里显示的是 `44 33 22 11`，和源码写的 `0x11223344` **顺序相反**。这就是**小端字节序**：低位字节存放在低地址处。这也说明了"地址小的字节才是变量的起点地址"。

### 2.2 指针变量和解引用操作符 `*`

```c
int a = 10;
int* p = &a;
```

- **指针**：就是内存地址，一个纯粹的编号；
- **指针变量**：专门用来存放地址的变量，它自己也要占一块内存空间。

![指针变量p与变量a的关系](https://aka.doubaocdn.com/s/nCNoQBg8Xm)

*图 2-4　p 申请的空间里存放的是 a 的地址*

`int*` 用来定义整型指针变量。写法的拆解如下：

- `*` 表示这是一个指针变量；
- `int` 表示这个指针**指向的对象是 int 类型**——它决定了将来解引用时访问几个字节。

解引用：

```c
int a = 100;
int* pa = &a;
*pa = 0;      // 等价于 a = 0
```

`*pa` 中的 `*` 是**解引用操作符**：取出 `pa` 里存的地址，顺着这个地址找到对应的内存空间。此时 `*pa` 就是变量 `a` 本身。

![a与p两块空间、&a与*p两套访问方式](https://aka.doubaocdn.com/s/W13ICx1nUj)

*图 2-5　`&a` 得到 a 的地址，`*p` 拿到 p 里存的那个地址所指向的空间*

> **思考**：既然可以直接写 `a = 0`，为什么要绕一圈用指针？
> 因为指针提供了**第二种修改变量的途径**。当变量在函数外部、而你人在函数内部时，只有地址能"传得进去"。后续函数传参（尤其是"通过函数修改外部变量"）会大量使用这一点。

### 2.3 指针变量的大小

指针变量存的是地址，地址位数由地址总线决定：

- **32 位机器**：地址 32 bit → 指针大小 **4 字节**
- **64 位机器**：地址 64 bit → 指针大小 **8 字节**

![32位(x86)平台下各类型指针的大小](https://aka.doubaocdn.com/s/TVTUnaCble)

*图 2-6　x86 平台（32 位）下 `sizeof(int*)` 等都是 4*

![64位(x64)平台下各类型指针的大小](https://aka.doubaocdn.com/s/qd8WcjG8Gf)

*图 2-7　x64 平台（64 位）下全部变成 8*

> **重点**：同一平台下，**所有类型的指针（`char*`、`int*`、`float*`、`double*`）大小完全相同**，只由机器位数决定，跟它指向什么类型毫无关系。

## 3. 指针变量类型的意义

指针变量的类型**不决定指针自身占多大空间，但决定两件关键的事**：

1. 解引用时**一次访问多少字节**；
2. 指针 ± 整数时**一步走多少字节（步长）**。

**示例 1：`int*` 指针**

```c
int a = 0x11223344;
int* p = &a;
*p = 0;
```

![int* 解引用前，a 的4个字节为 44 33 22 11](https://aka.doubaocdn.com/s/tTisywSX4H)

*图 3-1　执行 `*p = 0` 之前*

![int* 解引用后，4个字节全部清零](https://aka.doubaocdn.com/s/j7oliTRtBT)

*图 3-2　执行 `*p = 0` 之后：4 字节被整体清零*

**示例 2：`char*` 指针**（同一个变量，换成 char\* 再去解引用）

```c
int a = 0x11223344;
char* p = &a;
*p = 0;
```

![char* 解引用后，只有最低1个字节被清零](https://aka.doubaocdn.com/s/BGiIjNOKhf)

*图 3-3　执行 `*p = 0` 之后：只有 `44` 变成 `00`，其余 3 字节原样保留*

> **总结（解引用权限）**
>
> | 指针类型 | 解引用访问字节数 |
> |---|---|
> | `char*` | 1 |
> | `short*` | 2 |
> | `int*` | 4 |
> | `double*` | 8 |
>
> 同一段内存，换个指针类型去写，改掉的范围就完全不同——这就是类型存在的意义。

## 4. void* 指针

普通指针类型：`int*`、`char*`、`float*` 等。

特殊指针：`void*`，**无具体类型的指针**，也叫**泛型指针**。

1. **优点**：可以接收任意类型变量的地址（不需要强制转换）；
2. **局限**：**不能直接解引用，也不能直接做 ± 整数运算**。编译器不知道它指向的对象占几个字节，既算不出访问长度，也算不出步长。

```c
int a = 10;
void* p = &a;

// *p = 20;    // 编译报错：不能对 void* 解引用
// p + 1;      // 编译报错/警告：不能对 void* 做算术
```

要用的时候，必须先强转成对应类型的指针：

```c
*(int*)p = 20;      // 先转成 int* 再解引用
```

`void*` 在库函数里很常见（如 `malloc` 返回 `void*`、`memcpy` 的参数），因为它能"接住任何地址"，但真正操作前一定要转回具体类型。

## 5. const 修饰指针

### 5.1 const 修饰普通变量

不加 const：

```c
int a = 10;
a = 20;        // 合法
printf("%d\n", a);   // 输出 20
```

![未加const时可以正常修改并输出20](https://aka.doubaocdn.com/s/DRNl2u9lr3)

*图 5-1　普通变量可以随意赋值*

加上 const：

```c
const int a = 10;
a = 20;        // 编译报错
```

![对const变量直接赋值报错 E0137](https://aka.doubaocdn.com/s/QhDVdToeEE)

*图 5-2　"表达式必须是可修改的左值"*

⚠️ **注意**：在 C 语言里，`const int a` 的 **a 仍然是变量**，只是不能通过 `a` 这个"名字"直接赋值，它**不是真正的编译期常量**。

```c
const int a = 10;
int arr[a] = { };    // 编译报错：表达式必须含有常量值
```

![const修饰的变量不能作为数组长度](https://aka.doubaocdn.com/s/dMi1wzPf3B)

*图 5-3　C 语言中 const 变量不能当数组长度用（C++ 才可以）*

既然不能直接赋值，能不能绕过名字、通过指针改？

```c
const int a = 10;
int* p = &a;
*p = 20;
printf("%d\n", a);   // 输出 20
```

![通过指针间接修改const变量，输出20](https://aka.doubaocdn.com/s/HSqmOYn1gU)

*图 5-4　C 语言语法允许这种间接修改（结果为 20）*

C 语言语法不阻止这种写法，但这是**未定义行为的边缘**：好比房门锁着，却有人从窗户伸手进去改动了里面的东西。如果希望连指针也不能改这块内存的值，就需要用 const 修饰指针。（GCC/Clang 把 `a` 优化进寄存器时，甚至可能出现打印值仍是 10 的情况，说明这种写法并不可靠。）

### 5.2 const 修饰指针变量

关键在于 `const` 在 `*` 的**左边还是右边**：

```c
int a = 10;
int b = 20;

int const * p = &a;   // const 在 * 左边
int* const q = &a;    // const 在 * 右边
```

**写法一：`const int *p`（等价 `int const *p`）——锁内容，不锁指向**

```c
int a = 10;
int b = 20;
int const * p = &a;
p = &b;       // 合法：p 的指向可以改
*p = 90;      // 编译报错：不能通过 p 修改指向的内容
```

![const在*左边：*p=90报错，p=&b合法](https://aka.doubaocdn.com/s/A1ZN2ealFr)

*图 5-5　`*p = 90` 被编译器拦住（E0137），`p = &b` 没有问题*

**写法二：`int *const p`——锁指向，不锁内容**

```c
int a = 10;
int b = 20;
int* const p = &a;
p = &b;       // 编译报错：p 的指向不能改
*p = 90;      // 合法：可以通过 p 修改内容
```

![const在*右边：p=&b报错](https://aka.doubaocdn.com/s/KIdR9BF4tG)

*图 5-6　`p = &b` 被编译器拦住，`*p = 90` 才是允许的那个*

| 写法 | 谁被锁住 | 允许 | 禁止 |
|---|---|---|---|
| `const int *p = &a;` | 指向的**内容** | `p = &b;` | `*p = 90;` |
| `int *const p = &a;` | 指针的**指向** | `*p = 90;` | `p = &b;` |

**口诀**：`const` 紧挨着谁，谁就被锁住——`const` 贴着 `*`（即 `*` 右边），锁的是指针本身（指向）；`const` 在 `*` 左边，锁的是 `*p` 指向的内容。

生活化比喻：

```c
int m = 10;    // 爸爸，手里有 10 块钱
int n = 100;   // 妈妈，手里有 100 块钱
```

- `int const *p = &m;`：爸爸不让你动他手里的钱（禁止 `*p = xxx`），但你可以把 p 改成指向妈妈（`p = &n`），换个人操作；
- `int *const p = &m;`：p 死死绑在爸爸身上，不能改指向（不能 `p = &n`），但允许你通过 p 改爸爸手里的钱。

**双重保护**（既不能改指向，也不能改内容）：

```c
int const  * const p = &a;
```

> 用途提示：函数参数里写 `const char *s` 是在告诉调用者"我只读，不会改你的字符串"；写 `char * const` 多用于数组名、硬件寄存器地址这类"地址固定、内容可变"的场景。

## 6. 指针运算

指针不是所有算术都支持。**只支持三类合法运算**：指针 ± 整数、指针 - 指针、指针比较。**指针相加、相乘、相除没有任何语义，禁止使用**。

### 6.1 指针 ± 整数

```c
int arr[5] = {1, 2, 3, 4, 5};
int* p = &arr[0];
```

`p + n` **不是**简单地把地址数值加 n，实际是：

> 新地址 = 原地址 + `n * sizeof(指针指向的类型)`

- `p + 1`：向后跳过 1 个 `int`，即 4 字节，指向 `arr[1]`；
- `p + 2`：向后跳过 2 个 `int`，即 8 字节，指向 `arr[2]`；
- `p - 1`：向前移动一个元素的大小。

```c
int* p = arr;      // 等价 &arr[0]
printf("%d\n", *p);        // 1
printf("%d\n", *(p + 1));  // 2
printf("%d\n", *(p + 4));  // 5
```

> **再次印证**：指针的类型决定它走一步的步长。
> 同一个地址转成 `char*` 后，`+1` 只前进 1 字节。

**边界规则**（考试和工程都常考）：

- 允许指针指向数组最后一个元素**再往后一个位置**（常用来作循环结束标记），但**不能对该位置解引用**；
- 不能把指针运算到数组起始位置**之前**；
- 越过这两个边界都属于**未定义行为**，程序可能崩溃或读到垃圾数据。

```c
int arr[5] = {0};
int* end = arr + 5;   // 合法：末尾后一个位置，可比较，不可解引用
for (int* q = arr; q != end; q++)
    *q = 1;           // 标准写法，安全
```

### 6.2 指针 - 指针

**只有两个指针指向同一块连续数组空间时，相减才有意义。**

结果不是字节数，而是：**两个指针之间相隔多少个对应类型的元素**。返回类型是 `ptrdiff_t`（有符号整数，定义在 `<stddef.h>`）。

```c
int arr[10] = {0};
int* p1 = &arr[0];
int* p2 = &arr[5];

ptrdiff_t diff = p2 - p1;    // 结果是 5，不是 20
printf("%td\n", diff);
```

典型用途：求数组元素个数。

```c
int arr[10] = {0};
printf("%d\n", (int)(&arr[9] - &arr[0]) + 1);   // 10
```

> 两个不同数组、两个不同变量的指针相减，结果没有业务意义，属于未定义行为。

### 6.3 指针的关系比较

同一块连续内存（数组）内的指针，可以用 `>`、`>=`、`<`、`<=`、`==`、`!=` 比较。地址越大表示越靠后。

```c
int* p1 = &arr[0];
int* p2 = &arr[5];
if (p2 > p1) { /* 成立：p2 在 p1 后面 */ }
```

> ❌ 两个无关指针比较大小，标准 C 属于未定义行为。
> ❌ 永远不要写 `p1 + p2`，没有任何语义，编译器只会警告。

**指针运算小结**

| 运算 | 是否有意义 | 结果含义 |
|---|---|---|
| `p + n` / `p - n` | ✅ | 按元素步长移动 n 个元素 |
| `p1 - p2`（同数组） | ✅ | 相隔的元素个数 |
| `p1 > p2`（同数组） | ✅ | 谁更靠后 |
| `p1 + p2` | ❌ | 无意义，地址相加没有业务含义 |
| `p * n` / `p / n` | ❌ | 无意义 |

## 7. 野指针

### 7.1 什么是野指针

**野指针：指针变量里存放的是一个随机、无效、不受程序管控的地址**——指针自己都不知道指向哪里。

⚠️ 一定要和**空指针**区分开：

| | 空指针 `NULL` | 野指针 |
|---|---|---|
| 值 | 人为赋值为 0（`NULL`） | 随机的垃圾地址 |
| 含义 | 明确表示"不指向任何有效内存" | 无任何含义 |
| 能否判断 | `if (p == NULL)` 可以 | 无法用简单判断识别 |
| 危害 | 解引用必崩，但至少可控 | 随机崩溃、内存被悄悄破坏 |

### 7.2 野指针的常见成因

**成因 1：定义后未初始化**

局部指针变量不初始化，里面是栈上的随机值。

```c
int* p;      // 未初始化，p 里是随机地址 → 野指针
*p = 10;     // 解引用非法内存，程序可能直接崩溃
```

**成因 2：指针越界访问**

指针运算越过数组合法范围，指向了不属于自己的内存。

```c
int arr[3] = {1, 2, 3};
int* p = arr;
for (int i = 0; i < 10; i++)
{
    *p = i;    // i >= 3 之后 p 已经越界，成为野指针
    p++;
}
```

**成因 3：指向的内存已经被销毁（悬空指针）**

*场景 A：函数返回局部变量的地址。* 局部变量在栈上，函数一结束，栈帧回收，返回的地址就失效了。

```c
int* test()
{
    int n = 100;
    return &n;      // ⚠️ n 在函数结束后销毁，返回的是无效地址
}

int main()
{
    int* p = test();
    *p = 200;       // 未定义行为：写到一块已经不属于你的栈空间
    return 0;
}
```

*场景 B：`free` 之后指针没有置 NULL。* `free` 只是把内存还给系统，指针变量本身还留着旧地址。

```c
int* p = (int*)malloc(sizeof(int));
if (p != NULL)
{
    *p = 10;
    free(p);        // 内存已归还
    // p 仍保存着原来的堆地址 → 悬空指针
    *p = 20;        // ⚠️ 错误：使用已释放的内存
    p = NULL;       // 正确做法：释放后立刻置空
}
```

### 7.3 如何规避野指针

1. **定义即初始化**：要么指向一个合法变量，要么置为 `NULL`。

```c
int* p = NULL;
int a = 10;
int* q = &a;
```

2. **`free` 之后立刻置 NULL**（避免重复释放和悬空访问）。

```c
free(p);
p = NULL;
```

3. **严禁返回函数内部局部（非 `static`）变量的地址**；需要返回就返回 `static` 变量、全局变量，或者用 `malloc` 申请堆内存（并约定由调用者释放）。
4. **做指针运算严格检查边界**，循环用"末尾指针"作为结束条件，而不是凭感觉数下标。
5. **解引用前判空**，函数参数入口处先做合法性校验。

> **关键提醒**：`if (p != NULL)` 只能挡住空指针，**挡不住野指针**——野指针的值不是 NULL，判断照样通过。所以防治野指针的关键是**从源头杜绝**（初始化、置空、不返回局部地址、不越界），而不是指望事后判断。
