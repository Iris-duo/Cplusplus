## 1. 位操作符知识点回顾

C 语言里常用的位操作符有四个：

| 操作符 | 名称 | 作用 |
| :---: | :--- | :--- |
| `&` | 按位与 | 二元，两个操作数对应位「全 1 才为 1」 |
| `\|` | 按位或 | 二元，两个操作数对应位「有 1 即为 1」 |
| `^` | 按位异或 | 二元，两个操作数对应位「相同为 0，相异为 1」 |
| `~` | 按位取反 | 一元，操作数每一位 0 变 1、1 变 0 |

在使用前，有两个前提必须先讲清楚，否则后面的题目全是雾：

1. **操作数必须是整数**（`char`、`short`、`int`、`long` 等）。`float`、`double` 不能用位操作符。另外，`char`、`short` 参与运算时会先**整型提升**成 `int`，所以本文统一用 32 位 `int` 举例。
2. **计算机内部是用补码参与运算的**，内存里存的是补码，位运算也是在补码上逐位进行的。所以想算对，得先会算原码、反码、补码。

### 1.1 原码、反码与补码

整数在计算机里有三种二进制表示形式：**原码、反码、补码**，结构都是：

```
符号位（1 位） + 数值位
```

其中符号位 **0 表示正数，1 表示负数**。

**（1）正数：原码 = 反码 = 补码，三者完全相同。**

**（2）负数：三者各不相同，转换规则如下：**

| 形式 | 规则 |
| :--- | :--- |
| 原码 | 符号位为 1，数值位是该数**绝对值**的二进制 |
| 反码 | **符号位不变**，数值位按位取反 |
| 补码 | **反码 + 1** |

一句话记忆：**「原码取反得反码（符号位不动），反码加 1 得补码」**。

![图 1：整数的三种表示形式](https://aka.doubaocdn.com/s/5ru6l1UUTO)

*图 1：整数的三种表示形式*

以 `5` 和 `-1` 为例：

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int a = 5;
    // a 是正数，原码、反码、补码三者相同
    // 00000000 00000000 00000000 00000101

    int b = -1;
    // b 是负数，三者不同
    // 原码：10000000 00000000 00000000 00000001
    // 反码：11111111 11111111 11111111 11111110  （符号位不变，数值位取反）
    // 补码：11111111 11111111 11111111 11111111  （反码 + 1，逢二进一）

    return 0;
}
```

注意 `-1` 这个例子：**它的补码是 32 个 1**。这个结论在后面的例题里会反复用到，可以记一下。

> 顺带一提：也正是因为用补码存储，`int` 在内存里其实是一个「模 2³² 的环形计数器」，所以 `~0` 才会等于 `-1`，后面 1.2.4 会验证。

### 1.2 四个位操作符的计算规则

下面统一用 `a = 3`、`b = -5` 这两个数来演示，先把它们的二进制写出来：

```c
int a = 3;
// a 为正数，补码与原码相同
// 00000000 00000000 00000000 00000011

int b = -5;
// 原码：10000000 00000000 00000000 00000101
// 反码：11111111 11111111 11111111 11111010
// 补码：11111111 11111111 11111111 11111011
```

> 记住：**下面所有的按位计算，用的都是补码这一行。**

#### 1.2.1 按位与 `&`

- **计算规则**：两个操作数的对应位，**有 0 则为 0，全 1 才是 1**。

```c
int a = 3;
int b = -5;
int c = a & b;
printf("a & b = %d\n", c);

// 逐位与（用补码计算）
// a: 00000000 00000000 00000000 00000011
// b: 11111111 11111111 11111111 11111011
// c: 00000000 00000000 00000000 00000011
// c 的符号位为 0，说明是正数，正数的原码 = 补码，所以 c == 3
```

#### 1.2.2 按位或 `|`

- **计算规则**：两个操作数的对应位，**有 1 则为 1，全 0 才是 0**。

```c
int a = 3;
int b = -5;
int d = a | b;
printf("a | b = %d\n", d);

// 逐位或（用补码计算）
// a: 00000000 00000000 00000000 00000011
// b: 11111111 11111111 11111111 11111011
// d: 11111111 11111111 11111111 11111011
// d 的补码与 b 的补码完全相同，所以 d == b == -5
```

#### 1.2.3 按位异或 `^`

- **计算规则**：两个操作数的对应位，**相同为 0，相异为 1**。

```c
int a = 3;
int b = -5;
int e = a ^ b;
printf("a ^ b = %d\n", e);

// 逐位异或（用补码计算）
// a: 00000000 00000000 00000000 00000011
// b: 11111111 11111111 11111111 11111011
// e: 11111111 11111111 11111111 11111000
// e 的符号位为 1，说明是负数，需要由补码倒推回原码：
// 补码 11111111 11111111 11111111 11111000
// 反码 11111111 11111111 11111111 11110111   （补码 - 1）
// 原码 10000000 00000000 00000000 00001000   （数值位取反）
// 即 e == -8
```

> 小提醒：由补码倒推原码时，顺序是「**减 1 得反码，再取反得原码**」，方向和前面正着推正好相反，别搞混了。

#### 1.2.4 按位取反 `~`

- **计算规则**：一元运算符，操作数**每一位 0 变 1、1 变 0**（包括符号位）。

```c
int f = ~0;
printf("~0 = %d\n", f);

// 0:  00000000 00000000 00000000 00000000
// ~0: 11111111 11111111 11111111 11111111
// 这个补码就是 -1 的补码（见 1.1 的结论），所以 f == -1
```

#### 1.2.5 完整测试代码

把四个操作符放在一起跑一遍：

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int a = 3;
    // a 的补码：00000000 00000000 00000000 00000011

    int b = -5;
    // 原码：10000000 00000000 00000000 00000101
    // 反码：11111111 11111111 11111111 11111010
    // 补码：11111111 11111111 11111111 11111011

    int c = a & b;
    int d = a | b;
    int e = a ^ b;
    int f = ~0;

    printf("a & b = %d\n", c);
    printf("a | b = %d\n", d);
    printf("a ^ b = %d\n", e);
    printf("~0    = %d\n", f);

    return 0;
}
```

运行结果应为：

```
a & b = 3
a | b = -5
a ^ b = -8
~0    = -1
```

![图 2：完整演示的运行结果](https://aka.doubaocdn.com/s/QTS4EZmUZh)

*图 2：完整演示的运行结果*

**本节小结**：位运算是「在补码上逐位做布尔运算」，正数看不出差别，**一碰负数就全靠补码撑着**。所以第 1 节的两张表（三种表示形式的转换规则、四个操作符的规则）是后面所有题的地基。

## 2. 例题讲解

### 2.1 不创建临时变量（第三个变量），交换两个整数

看到「交换」，第一反应都是用第三个变量：

```c
int tmp = a;
a = b;
b = tmp;
```

但这道题偏偏不让用。那怎么办？思路是：**把「暂存」这件事交给 `a`、`b` 自己来完成**——先把它们「合并」成一个数，再从合并后的数里把各自的原始值「拆」出来。

#### 方法一：加减法

```c
int a = 3;
int b = 5;
printf("交换前：a = %d, b = %d\n", a, b);

a = a + b;   // 此时 a 存放的是「两数之和」
b = a - b;   // 用「和 - b」得到原来的 a，赋给 b
a = a - b;   // 此时 a 仍是「和」，b 已是原来的 a，用「和 - b」得到原来的 b

printf("交换后：a = %d, b = %d\n", a, b);
```

推演一遍（`a = 3, b = 5`）：

| 步骤 | 语句 | a | b |
| :---: | :--- | :---: | :---: |
| 初始 | — | 3 | 5 |
| ① | `a = a + b` | 8（和） | 5 |
| ② | `b = a - b` | 8 | 3（原 a） |
| ③ | `a = a - b` | 5（原 b） | 3 |

![图 3：加减法交换的运行结果](https://aka.doubaocdn.com/s/VeEzLcJ95D)

*图 3：加减法交换的运行结果*

**这种写法能完成任务，但有一个致命缺陷：溢出。**

当**相加的结果超过 `int` 能表示的最大值（2147483647）**时，`a + b` 这一步就已经溢出了。下图为了把溢出「可视化」，故意让 `a` 取了一个远超 `int` 范围的数 `21474836471`——你会发现**交换结果居然还是对的**，这正是补码「环绕」带来的假象。但它属于**未定义行为**（有符号整数溢出在 C 标准里是 UB）：换个编译器、开个 `-O2` 优化，结果就未必靠得住了。所以这种方法在工程上不推荐。

![图 4：加减法在接近 int 极限时出现溢出](https://aka.doubaocdn.com/s/vYQ8SbPaka)

*图 4：加减法的溢出演示（a 取了超出 int 范围的数，交换结果看似正确）*

#### 方法二：异或法（推荐）

```c
a = a ^ b;
b = a ^ b;
a = a ^ b;
```

第一次看到这三行长得一模一样的代码，多数人的反应是「这是什么？」。其实它背后只有两条异或的性质：

由「相同为 0，相异为 1」可以直接推出：

- **`a ^ a = 0`**（每一位都和自己相同，全是 0）
- **`a ^ 0 = a`**（每一位和 0 异或，保持原样）
- 以及**异或满足交换律和结合律**：`a ^ b == b ^ a`，`(a ^ b) ^ c == a ^ (b ^ c)`

据此逐行推导（设初始值为 `a₀`、`b₀`）：

```c
a = a ^ b;   // 此时 a = a₀ ^ b₀，b 仍是 b₀
b = a ^ b;   // b = (a₀ ^ b₀) ^ b₀ = a₀ ^ (b₀ ^ b₀) = a₀ ^ 0 = a₀   ← b 已变成原来的 a
a = a ^ b;   // a = (a₀ ^ b₀) ^ a₀ = b₀ ^ (a₀ ^ a₀) = b₀ ^ 0 = b₀   ← a 已变成原来的 b
```

交换完成，而且**全程没有用到第三个变量**。

**那它会不会溢出？完全不会。** 因为异或是**逐位独立运算、不产生进位**的，每一次运算的结果都必然落在原来的位宽里，自然不会溢出。这也是它比加减法更稳妥的原因。

**补充说明：**

1. 这个技巧**只对整数有效**，浮点数不能用（位运算不支持浮点）。
2. 如果 `a` 和 `b` 是**同一个变量**（比如 `swap(&x, &x)`），`a ^ a = 0` 会把这个值直接清零。所以用指针实现版本时要先判断地址是否相同，或者干脆别用异或法。
3. 可读性上，异或法对新手不友好，团队协作中一般仍然推荐用临时变量——**这题考的是「理解」，不是「工程实践」**。

### 2.2 求一个整数二进制中 1 的个数

题目：输入一个整数，输出它存储在内存中的二进制表示里 `1` 的个数（也就是统计补码中 1 的数量）。

> 这也是 LeetCode 191 题「位 1 的个数」的原型。

#### 方法一：`% 2` 取余法（只对正整数有效）

最容易想到的思路：不断对 2 取余、除以 2，余数为 1 就计数。

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int n = 0;
    printf("请输入要统计的整数:> ");

    while (scanf("%d", &n) != EOF)
    {
        int count = 0;
        int tmp = n;          // 用临时变量递推，保留原始的 n 用于输出

        while (tmp)
        {
            if (tmp % 2 == 1) // 最低位是 1 就计数
            {
                count++;
            }
            tmp /= 2;         // 整体右移一位的效果
        }

        printf("%d 的二进制表示中有 %d 个 1\n", n, count);
    }

    return 0;
}
```

![图 5：取余法统计 1 的个数（正数正确，负数出错）](https://aka.doubaocdn.com/s/wk2AGyVjbE)

*图 5：取余法统计 1 的个数（正数正确，负数出错）*

**问题来了：正数完全正常，负数却算不出来。**

以 `-1` 为例，手工走一遍循环：

- `-1 % 2 == -1`，**不是 1**，所以 `if` 条件不成立，`count` 不加；
- `-1 / 2 == 0`（C 语言整数除法向零取整），循环直接结束；
- 于是输出 `0` 个 1。

而 `-1` 的补码是 32 个 1，正确答案应该是 **32**。

> **这里有个特别容易写错的知识点**：C 语言中取余的结果符号**与被除数一致**，所以 `-1 % 2` 的结果是 `-1`，`-3 % 2` 也是 `-1`，而不是大家直觉中的 `1`。原文如果写成「`-1 % 2 = 0`」是不对的，实际是 `-1`——正因为它是 `-1` 而不是 `1`，判断 `tmp % 2 == 1` 才会永远失败。
>
> 另外，`tmp /= 2` 对负数也走不到「把 32 个 1 数完」那一步，因为它很快就变成 0 了。

所以这条路**只适合正整数**，负数必须换思路。

#### 方法二：移位 + 按位与，逐位判断（对负数同样有效）

一个 `int` 有 32 位，那能不能干脆**一位一位地看**？

思路是这样推导出来的：

```c
int a = 3;
// a: 00000000 00000000 00000000 00000011
// 1: 00000000 00000000 00000000 00000001
// 让 a 和 1 做按位与（规则：全 1 才是 1）
// 结果最低位是 1 → 说明 a 的最低位为 1，计数 +1
```

判断完最低位后，怎么判断下一位？**把 `a` 整体右移**，让原来第 2 位来到最低位，右侧补 0，再和 `1` 做按位与即可。循环 32 次，每一位都不会漏。

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int n = 0;
    printf("请输入要统计的整数:> ");

    while (scanf("%d", &n) != EOF)
    {
        int count = 0;
        int i = 0;

        for (i = 0; i < 32; i++)
        {
            if (((n >> i) & 1) == 1)   // 把第 i 位移到最低位，再与 1
            {
                count++;
            }
        }

        printf("%d 的二进制表示中有 %d 个 1\n", n, count);
    }

    return 0;
}
```

输入 `-1`，输出 `32`，正确。

![图 6：移位法统计 -1，得到 32 个 1](https://aka.doubaocdn.com/s/pMKrr29d7R)

*图 6：移位法统计 -1，得到 32 个 1*

**小坑提示**：`n >> i` 中 `n` 是**有符号**的，负数右移通常执行「算术右移」（高位补符号位 1），在绝大多数编译器上结果是我们要的。但严格来说，**有符号负数右移在 C 标准里是实现定义行为**。想写得绝对标准，可以把它转成无符号：`((unsigned)n >> i) & 1`。

这个方法**无论正负都正确**，但不管输入是什么都要固定循环 32 次，效率上还有优化空间——于是就有了方法三。

#### 方法三：`n & (n - 1)` 算法（推荐）

先直观感受一下这个表达式在做什么。以 `n = 15` 为例，只写二进制的后四位：

```
n     1111
n-1   1110
n&(n-1) 1110      ← 最低位的 1 变成了 0

n     1110
n-1   1101
n&(n-1) 1100      ← 又一个 1 变成了 0

n     1100
n-1   1011
n&(n-1) 1000      ← 继续

n     1000
n-1   0111
n&(n-1) 0000      ← 最后这个 1 也被消掉了
```

规律很明显：

> **`n & (n - 1)` 的作用：把 `n` 的二进制表示中「最低位的那一个 1」改成 0，其余位不变。**

**为什么会这样？** 减 1 的时候，最低位的 1 会变 0，而它右边的所有 0 全部变 1（就像十进制里 `1000 - 1 = 0999`）；再和原来的 `n` 做按位与，那个位置上的 1 就被消掉了，右边的部分又因为 `n` 本身是 0 而被「与」回去。所以每执行一次，`n` 里就少一个 1。

于是统计就变得非常简单：**能执行几次，就有几个 1**。

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int n = 0;
    printf("请输入要统计的整数:> ");

    while (scanf("%d", &n) != EOF)
    {
        int count = 0;
        int tmp = n;

        while (tmp)                 // 1 全部消完，tmp 变成 0，循环结束
        {
            tmp = tmp & (tmp - 1);  // 消掉最低位的 1
            count++;
        }

        printf("%d 的二进制表示中有 %d 个 1\n", n, count);
    }

    return 0;
}
```

![图 7：n & (n-1) 算法的运行结果](https://aka.doubaocdn.com/s/fRMb7AKG6G)

*图 7：`n & (n-1)` 算法的运行结果*

**三种方法对比：**

| 方法 | 循环次数 | 是否支持负数 | 适用场景 |
| :--- | :---: | :---: | :--- |
| `% 2` 取余法 | 与位数相关 | ❌ | 只用于讲原理 |
| 移位 + `& 1` | 固定 32 次 | ✅ | 通用，思路直观 |
| `n & (n-1)` | **等于 1 的个数** | ✅ | **最优，面试首选** |

`n & (n-1)` 的循环次数**只取决于 1 的个数**，输入 `0` 时一次都不执行，是三种里最快的。这个表达式还有很多衍生用法（判断 2 的幂、判断二进制中 1 是否只有一个等），后面可以单独开一篇讲。

### 2.3 把二进制某一位修改为 1 或 0

**题目**：把 `13` 的二进制序列的**第 5 位**修改为 `1`，再改回 `0`。

> 位置编号约定：从右往左数，最低位是**第 1 位**（下标 0）。所以「第 5 位」对应的是 `1 << 4`。

#### 分析

先写出 `13` 的二进制（只写后 8 位，方便看）：

```
13 = 00001101
       ↑
     第5位（下标4），当前是 0
```

**（1）把某位置 1 → 用「按位或」**

目标位与 `1` 做按位或，其余位与 `0` 做按位或：

- 目标位：`0 | 1 = 1`（置 1 成功）
- 其余位：`x | 0 = x`（保持不变）

所以工具是一个「只有目标位为 1、其余全 0」的掩码，即 `1 << 4 = 00010000`：

```
n     00001101
mask  00010000   (1 << 4)
n|mask 00011101   = 29
```

**（2）把某位清 0 → 用「按位与」，且掩码取反**

目标位与 `0` 做按位与，其余位与 `1` 做按位与：

- 目标位：`1 & 0 = 0`（清 0 成功）
- 其余位：`x & 1 = x`（保持不变）

这个掩码就是上面的 `1 << 4` 取反，即 `~(1 << 4) = 11101111`：

```
n      00011101
mask   11101111   (~(1 << 4))
n&mask 00001101   = 13
```

#### 代码

```c
#define _CRT_SECURE_NO_WARNINGS 1
#include <stdio.h>

int main()
{
    int n = 13;
    printf("原始值：%d\n", n);
    // 13 = 00000000 00000000 00000000 00001101

    n |= (1 << 4);            // 第 5 位置 1：00011101 → 29
    printf("第5位置1：%d\n", n);

    n &= (~(1 << 4));         // 第 5 位清 0：回到 00001101 → 13
    printf("第5位清0：%d\n", n);

    return 0;
}
```

**本节小结（记住这两句话就够用）：**

- **置 1 用「或」**：`n |= (1 << k)`
- **清 0 用「与取反」**：`n &= ~(1 << k)`
- 顺手再加一条：**取反某一位用「异或」**：`n ^= (1 << k)`（0 变 1、1 变 0，一次搞定）

## 3. 总结 & 位运算常用技巧速查表

三道例题背后，其实是同一套思路：**用「掩码 + 位操作符」精确地控制某几位，而不影响其他位**。

- 想**保留**某些位 → 用 `&`（与 1 得原值）
- 想**强制置 1** → 用 `|`（或 1 得 1）
- 想**强制清 0** → 用 `& ~`
- 想**翻转**某些位 → 用 `^`（异或 1 得反转）
- 想**判断**某位 → 用 `>>` 移到最低位再 `& 1`

### 位运算常用技巧速查

| 目的 | 写法 | 说明 |
| :--- | :--- | :--- |
| 判断奇偶 | `n & 1` | 结果为 1 是奇数，0 是偶数 |
| 第 k 位置 1 | `n \|= (1 << k)` | k 从 0 开始 |
| 第 k 位清 0 | `n &= ~(1 << k)` | |
| 第 k 位取反 | `n ^= (1 << k)` | |
| 判断第 k 位 | `(n >> k) & 1` | 或 `n & (1 << k)` |
| 消掉最低位的 1 | `n & (n - 1)` | 统计 1 的个数核心 |
| 取出最低位的 1 | `n & (-n)` | lowbit，树状数组的基础 |
| 判断是否 2 的幂 | `n > 0 && (n & (n - 1)) == 0` | 2 的幂二进制只有一个 1 |
| 交换两个数 | `a ^= b; b ^= a; a ^= b;` | 注意不能是同一变量 |
| 取绝对值（32 位） | `(n ^ (n >> 31)) - (n >> 31)` | 利用符号位 |

### 避坑清单（新手最容易错的四点）

1. **运算用的是补码**，不是原码、反码。正数三码合一，所以感觉不出来；负数才见真章。
2. **`-1 % 2 == -1`**，取余结果的符号跟随被除数，`tmp % 2 == 1` 对负数永远不成立。
3. **`<<`、`>>` 的优先级比 `+`、`-` 低**，写 `1 << 4 + 1` 会变成 `1 << 5`。凡是用到位运算，**建议一律加括号**。
4. **`~`、`!`、`-` 是一元运算符，优先级很高**，`~(1 << 4)` 这种嵌套写法要保证括号正确；另外 `~` 不会改变数据类型，但会得到「全部位取反」的值，容易在 `unsigned` 与 `signed` 混用处出问题。

位运算看着抽象，本质就是把整数当成一排开关来操作。
